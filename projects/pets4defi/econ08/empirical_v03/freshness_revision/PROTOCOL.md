# Descriptive extension protocol, 17 November 2026

The original 90-day EAS feasibility screen and its thresholds remain a historical result. This separate 180-day descriptive study uses [2026-05-21 00:00 UTC, 2026-11-17 00:00 UTC). All summaries use UTC and report coverage by source. Freeze this document in Git before downloading extended observations. The overlapping 90 days were already known.

* EAS on Ethereum, Base, Optimism, Arbitrum One, Linea and Scroll, and Verax on Linea as a separate registry. Check official deployment, chain and endpoint. Count only on-chain revocations. Use at least ten distinct revocation days and at least 1,000 attestations issued before window end per attester for descriptive qualification. The original target of four independent sources is unchanged. Report chain-address keys and possible common operators conservatively in aggregates. A count failure remains unknown. Changes in registry coverage, method and source semantics are recorded separately. Do not pool Verax portal and issuing-entity identities without an attested mapping.
* Web PKI. Start with the CCADB catalogue of TLS-capable intermediates. Distinguish CA organization, signing key, cross-signs and CRL shard. Treat one CA organization as a dependence cluster. Inventory signed full CRLs with issuer and signature checks, separate thisUpdate (publication), nextUpdate (deadline), and revocationDate (effective event). Use archives with known coverage to estimate historical flows. One present-day full CRL is a censored stock. Record snapshot date, shards, retention/expiry and missing coverage. Report stock-only or incomplete sources separately. No pooling of Web PKI with DeFi issuers.
* Accesses. Make one bounded Dune attempt for Aave v3 Base supplies and withdrawals. Pairs use the economically relevant beneficiary/owner and are deduplicated per address and transaction. Return only aggregate interval bins, numbers of wallets with 1, 2, or >=3 accesses, calendar/within-day summaries when available, and aggregate pair counts. No addresses leave the query. Bound the attempt to at most 48 hours. A failed request is an availability result. Marginal gaps can support renewal-model calibration, but preserve neither wallet sessions nor cross-source correlation.
* Fees. Base mainnet historical L2 base price and L1 data fee for each fixed serialized reference transaction at the same historical block. Predefine one checkpoint at/after 12:00 UTC on each date in the original 90-day window (90 observations), report availability, L2 gas, exact quotation method, applicable fork/additional components, paired estimates and missingness. Use no gas-price average from a different network. Quote the modeled base-fee scenario with zero tip and state this assumption. A free supplementary sample using retrievable canonical blocks is labelled separately if the 90-day series is incomplete.
* Fixed cases. Evaluate batch P = 1, 6 and 24 hours, and F = 1, 6 and 24 hours with P = F - 300 seconds. Report event-driven policies under the same SLA and slot-aligned policies at identical P and assumed L. Include selective, cover (rho = 0.5), common, always-publish batch and grouped epochs. Group size G means issuers per group. Include prespecified random groups and like-with-like groups based on the template class. Publish exact per-seed aggregates and within-seed comparisons. Event times for subdaily analysis are derived from the previous Base window or explicitly generated under named synthetic assumptions.
* Only derived aggregate schedules, statistics and origin documentation are released. The descriptive work may stand on its own when some sources are unavailable. Retain all specified failures and do not select only favorable networks, seeds or time windows.
